# 生产化演进路线

原则：先把状态、协议、风控和可观测性做正确，再追求低延迟。不要把“多语言”误当成“生产级”。

## Phase 0：当前本地 MVP

已完成：

- Go HTTP 控制面；
- C++ 模拟执行核心；
- Scala SMA 因子任务；
- Java 基础回测；
- 本地 NDJSON 管道；
- 风险限制和 smoke 测试；
- 架构、接口、研究、开发文档。

明确不支持：真实行情、真实账户、真实订单、持久化、断线恢复、成本模型。

## Phase 1：研究平台可复现

目标：让每次回测都能复现。

- 引入 Parquet 数据层；
- 增加数据 schema 和版本号；
- 按 symbol 分组并校验交易日；
- 因子计算结果带参数 hash；
- Java 回测输出完整指标；
- 增加手续费、滑点和成交延迟；
- 增加样本外和 walk-forward；
- 把运行元数据写入 PostgreSQL 或实验仓库。

验收：同一数据版本、策略版本和参数 hash 重跑，结果一致。

## Phase 2：仿真盘

目标：用接近真实的执行模型验证订单生命周期。

- 订单状态机：NEW、ACCEPTED、PARTIALLY_FILLED、FILLED、CANCELED、REJECTED；
- order_id 幂等；
- 撤单和改单；
- 部分成交、盘口深度和成交延迟；
- 账户资金冻结、释放和结算；
- 事件序号、重放和断点续传；
- Redis/数据库只做状态辅助，审计事件采用 append-only 记录。

验收：控制面重启后可从事件日志恢复订单和账户状态。

## Phase 3：真实行情接入

目标：只接收真实行情，不发真实交易单。

- 行情 adapter 与统一 `MarketDataEvent`；
- sequence 检查、乱序检测和断线重连；
- 交易日历和时钟同步；
- 行情延迟、丢包和质量指标；
- 只读权限和密钥隔离；
- 仿真盘使用同一套事件模型。

验收：行情断线、重连、乱序和重复消息都有可观测结果。

## Phase 4：灰度交易

目标：小规模、强约束、可人工熔断。

- 券商/交易所 adapter 独立进程；
- 订单发送前最后一道风控；
- kill switch、日亏损限额和异常波动熔断；
- 账户、订单、成交和资金四账对账；
- 审计日志不可篡改；
- 单策略、单账户、低额度灰度；
- 人工审批和回滚预案。

验收：模拟故障时能停止发单，并能确认未确认订单最终状态。

## Phase 5：规模化

目标：在收益逻辑之外解决可靠性、容量和运营问题。

- 多策略组合和风险预算；
- 因子 IC/IR、拥挤度和失效监控；
- VaR/CVaR 和历史压力场景；
- Prometheus/Grafana 指标；
- 高可用、灾备、跨机房和恢复演练；
- C++ 热路径基准、内存分配审计和延迟分位数；
- Go 控制面水平扩展，执行核心按账户/市场分片；
- Scala/Spark 承担大规模批处理，Java 负责实验编排和结果服务。

## 禁止跳过的门槛

```text
研究可复现
  -> 仿真成交可信
  -> 事件可恢复
  -> 风控可熔断
  -> 账务可对账
  -> 小额灰度
  -> 才考虑扩大资金规模
```
