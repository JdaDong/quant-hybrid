# 风险边界与上线前检查

## 1. 当前系统的真实能力

当前系统能证明：

- 四种语言可以通过清晰的文件和进程边界协作；
- Go 可以对订单做基础参数和仓位限制；
- C++ 可以执行一个确定性的本地模拟成交；
- Scala 可以生成简单均线信号；
- Java 可以计算一个不使用 T+1 未来数据的基础回测；
- smoke 测试可以覆盖从 HTTP 到模拟成交的最短链路。

当前系统不能证明：

- 策略有真实市场 alpha；
- 回测收益在真实成交中可实现；
- 订单在网络、进程或机器故障后不丢失；
- 资金和仓位账在重启、重复回报后仍然正确；
- 真实交易所协议、限频、交易时段和风控规则已经适配；
- 多策略并发运行时的组合风险可控。

## 2. 不可接受的生产缺口

以下任一项未完成，都不应接入真实资金：

- 没有订单幂等和最终状态查询；
- 没有持久化事件和恢复机制；
- 没有交易所成交回报对账；
- 没有资金、持仓、订单、成交四账；
- 没有 kill switch；
- 没有日亏损、单策略、单标的和组合风险限额；
- 没有密钥隔离和最小权限；
- 没有时钟同步和事件时间口径；
- 没有压测、故障演练和恢复演练；
- 只有单一来源的行情或成交状态。

## 3. 风控分层

```text
策略层：信号合法性、仓位目标、调仓频率
    ↓
组合层：beta、行业、标的集中度、杠杆、相关性
    ↓
订单层：数量、价格、名义金额、方向、频率、幂等
    ↓
执行层：交易时段、涨跌停、盘口、部分成交、撤单
    ↓
账户层：余额、冻结、可用资金、日亏损、总敞口
    ↓
系统层：延迟、断线、重复事件、时钟、进程存活
```

## 4. 发布前检查清单
