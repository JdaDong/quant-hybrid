混合语言量化交易系统 MVP

实时路径保持短而硬：Go 控制面 → C++ 执行核心。研究路径异步解耦：Scala 因子批处理 → Java 回测。四种语言各司其职，不把 Spark/Scala 塞进交易热路径。

职责边界

Go：控制面

HTTP API、订单校验、风险门禁、OMS 状态、进程管理、事件转发。

C++：执行核心

NDJSON 订单协议、内存持仓、模拟撮合、低延迟风险前置。未来替换为柜台/交易所适配器。

Scala：因子批处理

读取历史行情，计算 SMA 因子和信号文件。未来可平滑迁移到 Spark + Parquet。

Java：回测与实验

严格使用下一交易日收益，输出收益、最大回撤和交易次数，作为策略验收基线。

数据流

prices.csv
历史行情→Scala FactorJob
SMA5/SMA10 信号→Java Backtest
避免前视偏差
HTTP /orders
策略或人工下单→Go control-plane
风险门禁 + OMS→C++ execution_core
撮合 / fill

协议与演进

当前本地 MVP 采用便于调试的 NDJSON；proto/events.proto 定义长期演进的 Protobuf 契约。生产化时建议：实时事件使用 FlatBuffers/Protobuf，研究数据使用 Parquet，审计账使用 PostgreSQL/ClickHouse。

明确不做的事：不接真实券商、不保存真实密钥、不默认产生真实订单。上线前必须补充交易所适配、幂等、断线重连、持久化、时钟同步、限频、审计、压测和灾备。
